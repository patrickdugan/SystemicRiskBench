# SRB-REV-05: Real BitAgent CPU pilot with a verified bounded-memory codec

Registered 19 November 2026. This public-development experiment is a small
GitHub-hosted **actual model-inference** check using the original frozen
SRB-REV-03 financial law, plus an explicitly marked arithmetic sidecar.
The implementation leaves `agent_revision.py`, `finance_revision.py` and
the source SHA-256-locked panel manifest unchanged.

## Registered model and CPU server

The model is the SHA-256-pinned
[Bonsai-8B Q1 GGUF](https://huggingface.co/prism-ml/Bonsai-8B-gguf/resolve/48516770dd04643643e9f9019a2a349cf26c5dbd/Bonsai-8B-Q1_0.gguf)
and
[BitAgent 8B LoRA](https://huggingface.co/AlephFunk/bitagent-bonsai8b-dagv2-lora-v3/resolve/ee2937fb58d87bbd155cd205c43dc8103b51eac2/bitagent-bonsai8b-dagv2-lora-v3-f16.gguf),
with 1-bit base quantization and LoRA scale 1.0. Each download verifies its
expected SHA-256 and byte count. The official
[llama.cpp release b12248 Ubuntu x64 CPU archive](https://github.com/ggml-org/llama.cpp/releases/tag/b12248)
is pinned to upstream commit
`3837bf0bc02ea5d08f8ee3585fc8c7784a81bce8` and SHA-256
`6b3a530b44f6b0a4ae4872d3b3c8d1edc2ac6bba7d8bd211329a4ba644c0dc65`.
The downloaded server executable is independently hashed at runtime and
registered before inference. The model and server binaries are stored only in
the ephemeral CI runner, outside Git.

Runtime: four CPU threads, `-ngl 0`, no flash attention, 4,096 context,
`max_tokens=256`, `temperature=0`, `seed=0`, and at most 150 seconds per
stage. A fresh OS `llama-server` process handles each stage. The resulting
OS process and listening port are verified closed before the next stage.

## Prespecified cases, arms, and primary outcomes

The two pilot roots are **indices 0 and 5** from the published pilot's six
roots. Index 5 is also in the stress panel; this overlap is declared.
There are four arms, each containing these same two cases:

| Memory mode | Treatment | Actual intervention |
| --- | --- | --- |
| count, 4 logical bits | model_memory | Model generates memory integer as before |
| count, 4 logical bits | verified_visible_codec | After model initial response, host substitutes exact sum of 12 initially visible bits |
| bitmap, 12 logical bits | model_memory | Model generates named-bit bitmap integer as before |
| bitmap, 12 logical bits | verified_visible_codec | After model initial response, host substitutes exact 12-bit mask |

Both treatments call the **same model** on their initial packets and ask the
model for its own posterior, action and memory. The host intervention affects
the integer in the **update packet only**, which also contains the six valid
replacement records. The initial forecast/action and subsequent updated
forecast/action are never rewritten by the host.

A verified-codec arm still fails at the initial stage if model transport,
JSON fields, posterior normalization, the bounded integer type, or action
syntax fails. The raw memory generated by the model is recorded separately,
including incorrect values, and the sidecar does not receive the hidden
regime. Previous transcripts and initial old records are absent from the
update request.

**Primary pass/fail gates:**

| Gate | PASS criterion |
| --- | --- |
| Exact visible-state codec | Host encoding matches the independently computed source-law old count/mask for all registered roots |
| Real inference observed | At least one transport receipt attests the verified pinned model/LoRA was genuinely invoked |
| Any assisted completion | At least one verified-codec case completes its update stage |
| Codec coverage lift | At least one memory mode scores more complete cases with verified state than the direct model-memory treatment |
| Per-stage reset integrity | Every attempted stage yields a unique server boot and verified process/port shutdown |

The first two gates are engineering observations. Completion and coverage
lift are **scientific results**, which may FAIL while the CI job still
succeeds. All missing cases retain their registered
`2.0` posterior-excess-Brier and `20.0` policy-regret penalties. Each
group reports model raw memory accuracy, valid-schema coverage, scored
coverage, posterior error, policy regret, own-forecast action coherence,
token usage, latency, and failed transport counts.

The experiment is **not compute-matched** with the prior GPU campaign, and
the pilot's small sample does not establish model competence or a population
effect. The verified state is host-provided algorithmic assistance; any
improvement cannot be credited to BitAgent's own memory encoder.

## Run and prompt integration

[GitHub Actions](../.github/workflows/rev05-cpu-bitagent.yml) runs
source-law and codec unit tests first, then downloads the registered CPU
server and model weights on the hosted Ubuntu runner, launches actual
`llama-server` stage subprocesses and archives the observed receipts.

The execution emits `observations.json` and a regenerated
`NEXT_PROMPT.md`, whose next-run instructions are chosen from the **actual
PASS/FAIL results**. When infrastructure fails, the prompt reports
`INFRASTRUCTURE FAIL` and preserves the exact source registrations. When
the assisted model completes without an improvement, it reports
`CODEC-LIFT FAIL` and focuses the next prompt on posterior normalization,
policy reasoning and compute matching. When lift appears, the next prompt
calls for independent-root and fixed-budget confirmation.

The artifact-publishing path stays under `artifacts/rev05-ci/`. Keep all
weights on the original Hugging Face hosts and preserve SHA-pinned URLs and
artifact hashes. Model JSON outputs and failed-call receipts are synthetic
public benchmark data, with `model_evaluation_claim=false` and
`physical_memory_enforced=false`.
